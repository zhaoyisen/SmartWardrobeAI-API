# 用户管理模块详细设计

## 1. 模块概述

用户管理模块用于在后端管理系统中维护两类用户：

- **管理端用户**（sys_user表）：后台管理员账号
- **App端用户**（users表）：移动端注册用户

### 1.1 功能定位

- 管理端用户：支持管理员账号的增删改查、状态管理、密码重置
- App端用户：支持查看、编辑、禁用/启用、删除等操作（不提供密码重置，由用户自行修改）

### 1.2 技术架构

- Controller层：RESTful API，使用Swagger文档注解
- Service层：业务逻辑处理，继承MyBatis-Plus的IService
- Mapper层：数据访问，继承BaseMapper
- DTO/VO模式：QueryDTO（查询参数）、SaveDTO（保存表单）、VO（返回对象）

## 2. 数据库设计

### 2.1 管理端用户表（sys_user）

已存在，字段包括：

- id：主键
- username：用户名（唯一）
- password：密码（BCrypt加密）
- nickname：昵称
- avatar：头像URL
- status：状态（1启用 0禁用）
- create_time：创建时间
- update_time：更新时间

### 2.2 App端用户表（users）

已存在，字段包括：

- id：主键
- username：昵称
- email：邮箱（唯一，登录凭证）
- phone：手机号（唯一，登录凭证）
- password_hash：密码（BCrypt加密）
- avatar_url：头像URL
- height：身高（cm）
- weight：体重（kg）
- create_time：创建时间
- update_time：更新时间

**注意**：两个表结构已存在，无需修改数据库。

### 5.2 核心业务逻辑

#### 5.2.1 管理端用户新增

1. 校验用户名唯一性
2. 密码使用BCrypt加密
3. 默认status=1（启用）
4. 保存到数据库

#### 5.2.2 管理端用户修改

1. 校验ID存在性
2. 校验用户名唯一性（排除自身）
3. 如果传了密码，则加密后更新；否则不更新密码
4. 更新其他字段

#### 5.2.3 管理端用户删除

1. 不能删除自己（通过UserContext.getUserId()判断）
2. 检查是否有关联数据（如果有业务关联）
3. 执行删除

#### 5.2.4 管理端用户重置密码

1. 校验用户存在
2. 生成默认密码（123456）的BCrypt加密值
3. 更新密码字段
4. 返回提示信息

#### 5.2.5 App端用户修改

1. 校验ID存在性
2. 校验邮箱唯一性（如果修改了邮箱，排除自身）
3. 校验手机号唯一性（如果修改了手机号，排除自身）
4. 不更新密码字段（密码由用户自行修改）
5. 更新其他字段

#### 5.2.6 App端用户状态管理

**前提**：需要先为users表添加status字段

```sql
ALTER TABLE users ADD COLUMN status TINYINT(1) DEFAULT 1 COMMENT '状态:1启用 0禁用';
```



## 6. 特殊说明（重点需求逻辑）

### 6.1 密码安全

- 所有密码必须使用BCrypt加密存储
- 管理端用户重置密码统一为：123456（加密后存储）
- App端用户密码不允许管理员重置，由用户自行修改

### 6.2 唯一性校验

- 管理端用户：username必须唯一
- App端用户：email和phone必须唯一（但允许其中一个为空）

### 6.3 删除限制

- 管理端用户：不能删除当前登录的管理员自己
- App端用户：删除前检查是否有关联数据（如clothing表）

### 6.4 状态管理

- 管理端用户：status字段已存在，直接使用
- App端用户：需要添加status字段（见5.2.6）

### 6.5 查询优化

- 使用MyBatis-Plus的QueryGenerator自动生成查询条件
- 支持模糊查询（用户名、昵称、邮箱、手机号）
- 支持精确查询（状态）

### 6.6 数据转换

- Entity转VO使用BeanUtils或Hutool的BeanUtil
